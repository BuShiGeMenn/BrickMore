# BrickMore：P_inv 与 VQAScore 测评方案

日期：2026-10-23。状态：设计方案，尚未安装新增依赖、下载 VQA 权重或运行这两项测评。

2026-10-24 官方来源核对补充：官方 README 明确要求复现论文原始碰撞数字时使用 **v0.1.0**。2026-10-01 的更新改用了复合凸包、Bullet 穿透深度和 1 LDU 容差；本文此前建议的检测器属于更新后的工程方案，不能据此声称复现论文原版 P_inv。当前官方渲染器另要求 Python 3.13+、Blender/bpy 5.1+，不能直接装进现有 Python 3.12 评分环境。详细来源见 `BRICKNET_OFFICIAL_EVALUATION.md`。

## 1. 建议与范围

建议分两条线推进：VQAScore 复用现有图片，先验证本机小模型；P_inv 先解决结构输入和指标口径，再开展碰撞检查。GLB 最终场景诊断与原始生成序列测评应分别命名。

现有数据：16 类、480 个候选，实际 GLB 918 份（raw 473、stitched 445），其中 438 个候选版本成对。已有 8 视角、512×512 的图片共 7,344 张，位于 `D:\BrickMore\Results\model_eval_20261021\renders`，可直接复用对应 manifest、prompt、图片哈希和渲染协议。

现有硬件：RTX 4050 Laptop 6GB；i7-14650HX；约 13.7GB 可用总内存。现有独立 Python 环境为 `D:\PythonEnvs\brickmore-eval`，Python 3.12.10、torch 2.8.0+cu128、transformers 4.57.1。环境继续放在项目外。

## 3. P_inv：结构有效性

### 3.1 当前缺口

论文把 P_inv 定义为无效放置的比例，越低越好。当前本地 `score.py` 输出动作数、首次无法解析的位置、解析成功前缀中的碰撞位置；CLI 汇总的“完全可解析且无碰撞的模型比例”并不是 P_inv。

当前 Model 文件夹只有 GLB 和查看器等辅助文件，没有原始 LDR/MPD、BrickNet path 或原始生成动作日志。元数据中的 OBJ 路径也不能替代这些输入。GLB 节点名称包含部分零件编号，可尝试提取最终位姿，但不能据节点顺序认定原始生成顺序。

### 3.2 首选：补原始结构/序列输入

每个候选、每个版本建立同一 sample_id 的结构记录，保留：

- 原始零件编号、颜色、位置、旋转和原始放置顺序，或原生 BrickNet path 文本。
- 坐标单位、坐标轴、零件库版本、raw/stitched 对应关系和文件哈希。
- 若要评价生成过程：保留解析失败、重试、被拒绝的动作，不能只交付修复后的成功结果。

BrickNet `score` 只接受其连接图路径语法。BrickGPT 的坐标式输出、LDR 或 GLB 需要对应适配器，不能直接当作 path 文本。禁止使用会过滤碰撞和丢弃分量的 `bricknet sample` 来制造待测路径，这会提前改变测评对象。

新实验的碰撞检测优先复用更新后的 BrickNet 复合凸包与 PyBullet，在 CPU 运行。冻结该版本的 1 LDU 穿透容差、边距修正、零件别名变换和已知合法固定连接的例外。若目标是复现论文原始数字，则改用官方指定的 v0.1.0 及其配套预内缩网格与碰撞算法，不沿用新版 1 LDU 检测配置。不能把积木外包围盒重叠直接判作碰撞，也不能仅凭 GLB 接触推定某个 fixed 例外。

建议先使用完整可解析、零件碰撞体齐全且保留原始顺序的样本，明确本项目的动作统计：

`p_i = 发生至少一次非法碰撞的放置动作数 / 该样本的放置动作总数`

同一动作碰到多个零件只计一次；已经碰撞的零件仍保留在场景中，遵循现有检测器的行为。报告同时给出模型平均 `mean(p_i)` 与动作加权平均 `sum(bad_i)/sum(n_i)`，明确区分。论文公开描述未充分展开全部聚合细节，最终论文对齐口径需核实，不能默认上述任一聚合等于论文表格实现。

对于语法或连接解析失败的序列，另报失败率、首次失败位置和可判定前缀长度。未解析的后缀是未知，不默认为成功，也不自动全部计失败。碰撞体缺失时记 NA，并报告覆盖率，不记零碰撞。论文文本条件实验会重生成不可解析序列；本项目已有样本无法恢复这一重试过程，必须披露差异。

### 3.3 仅有 GLB 时的可执行替代

先抽取少量 GLB，验证：层级世界变换、每个物理零件的边界、零件编号、导出轴向与缩放、LDU 换算，以及别名变换。用标准积木尺寸与重建后的形状做双重校验；不能仅凭文件显示单位假定转换正确。

只有零件和位姿能可靠恢复时，才扩展到全量。若导出合并网格、缺失零件标识或变换不可恢复，则停止该样本的结构评分并记录原因。

此路线输出独立指标：

- `collision_part_fraction`：参与至少一对非法穿透的零件数 / 可评估零件数。
- `collision_free_model_rate`：零碰撞模型比例。
- 碰撞对列表、穿透深度、零件/碰撞体覆盖率。

这些是最终场景的碰撞诊断，不命名为原版 P_inv。碰撞检查也不能证明模型连通、稳定或可按现实顺序装配；连通分量等可另设辅助指标。

## 4. VQAScore：图文符合程度

### 4.1 固定评分协议

直接读取现有 `manifest.jsonl` 和 `renders.jsonl`，按 sample_id 关联原始英文 prompt。每个 GLB 使用全部 8 张图，不按 SigLIP2/PE 的最佳视角预筛选，不重新生成图像。

为对齐本地脚本，问题模板为：

`Is this LEGO set {caption}?`

caption 合并多余空格、去掉末尾句末标点并转小写，与原函数一致。不沿用 PE 的 32-token 截断；检查 VQA 实际输入长度，超限必须显式记录。

每张图独立向模型提问，提取第一个回答 token 为 `Yes` 的概率：

`s_ij = softmax(first_answer_logits.float())[yes_token_id]`

这是整个词表上的概率。不能改成 Yes/No 两项归一化，也不能把生成回答中的 yes 次数当概率。先验证 `Yes` 在该 tokenizer 和回答边界下的编码，不盲目使用 `encode("Yes")[0]`。如果模型回答模板不同，应明确另设协议。

每个 GLB 主分数为 `max(s_i0, ..., s_i7)`，总体为逐 GLB 主分数的均值。附带保存八视角均值、最低值、最佳视角和全量视角概率，便于检查 max 聚合是否掩盖侧面缺陷。缺任一视角的样本记录失败，不用不足八张的 max 冒充完整分数。

先采用与原脚本一致的一步 generate。若改成直接 forward 读取最后位置 logits，必须验证与生成端的 logits 处理后概率一致再替换。

### 4.2 本机运行配置

- 第一阶段：Qwen2-VL-2B-Instruct、BF16、SDPA、batch_size=1、num_workers=0，每次仅处理一个视角。评分模型与 SigLIP2/PE 依次加载运行。
- 首轮建议图像上限设为 `max_pixels=256*28*28`（正方形约 448×448），最低像素设为 `64*28*28`。这是本机方案的处理预算，与原脚本默认处理器不同，必须写入配置。
- 先完成 8 份 GLB、64 次单视角推理的检查，测峰值显存、RAM、耗时与数值。6GB 能否稳定完成以实测为准，不能仅凭 2B 参数量保证。
- 若显存不足，另试明确标注的 4-bit 配置，先验证 Windows、CUDA 和量化后端兼容性，以及概率输出正常；不要在一次全量任务中按样本自动切换精度或图像预算。
- 若 BF16 与量化配置均不可用，再考虑更大显存设备。原版 7B 不作为本机首选；CPU 卸载还会受到本机内存限制。
- 大显存复核可先按单卡 24GB、系统内存至少 32GB 做工程预算，batch 仍从 1 开始，最终由模型和输入的实测决定。该建议不是显存保证。

模型权重和处理器须固定 Hugging Face revision，保存模板、dtype、量化参数、像素预算、tokenizer、Yes token ID、依赖锁文件和代码哈希。2B/量化版结果明确标为本地实验指标，不作为 7B 的等价替代。

### 4.3 图像可评价范围

现有图片统一为黄色材质，颜色符合度无法可靠评价。L4/L5 的长提示词可以完整输入 VQA，但隐藏结构、装配稳定性、精确零件数等属性仍不能仅由图片确认。可另做“类别/外形/可见部件”的属性问答分析，但不能将它替换为主 VQAScore 或据此宣称物理有效。

## 5. 环境与存放位置

P_inv 的增量依赖来自本地 bricknet 包：numpy、scipy、pybullet>=3.2.7、platformdirs；碰撞体/零件库下载到项目外，例如 `D:\PythonEnvs\brickmore-eval\cache\bricknet`，运行前核对 BrickNet 实际的数据目录配置方式。

VQA 需要兼容当前 transformers 的 accelerate、qwen-vl-utils 及其依赖。先核查已有安装，解析兼容版本并锁定；本方案不指定未经验证的新增版本号。

优先在现有环境做依赖解析预检。若量化后端等要求替换核心依赖，则新建 `D:\PythonEnvs\brickmore-vqa`，沿用 Python 3.12 和可用 CUDA PyTorch 组合。无需 Anaconda，也无需为这项任务额外安装完整 CUDA Toolkit。

不要直接向现有可用环境执行无版本限制的 `pip install -U t2v-metrics`：当前官方 3.1 要求 transformers>=5，而现有环境为 4.57.1。本项目可直接适配已有 Qwen 评分脚本，不必引入整套工具；若需要原始 VQAScore 工具链复现，则单独锁定对应版本和环境。

## 6. 实施顺序与验收

1. **输入审计**：从原 manifest 建立 sample_id 对应表；查原始结构文件可获得性；抽取 GLB 零件与位姿并做转换校验，输出覆盖率。
2. **基础正确性**：结构端用无碰撞、明显穿透、正常积木咬合、重复零件、缺碰撞体和解析失败样例验证；VQA 端检查 Yes 编码、模板、概率和八视角聚合。使用匹配/错配 caption 作敏感性诊断，不要求每个样本都单调正确。
3. **本机试跑**：先 8 份 GLB；通过后选每类 L1/L3/L5 各一个完整配对候选，约 96 份 GLB、768 张图，具体受数据齐全情况限制。冻结配置后才扩展全量。
4. **实测预算**：用预跑的实际单视角耗时估算 `7344 × 单视角平均耗时`，加上加载与预处理时间；记录峰值显存、RAM、失败原因，不提前承诺耗时。
5. **全量与断点续跑**：VQA 目标 918 份/7,344 张图；结构指标只覆盖输入合格的样本。按 sample_id、配置和输入哈希续跑，禁止混用不同配置的缓存。
6. **统计与复核**：raw/stitched 分开，按 16 类和 L1–L5 分组；stitching 改变量仅计算 438 个完整配对候选中两项评分均成功的子集，同时给实际 n。VQA 越高越好，P_inv/碰撞比例越低越好。

建议在配对候选层面 bootstrap 给出改变量的置信区间，八张视角不能当作八个独立模型。原 prompt 随等级/候选变化时，额外用每类固定的对象名称问句做敏感性分析，单独输出；主评分仍使用原始完整 prompt，不据跨等级分数直接推断生成能力。

## 7. 拟交付文件

代码新增独立适配器，例如 `evaluate_structure.py` 和 `evaluate_vqa.py`；避免修改已完成 SigLIP2/PE 运行所依赖的代码签名。新结果拟放到 `D:\BrickMore\Results\structure_vqa_20261023`，运行时再创建。

- `input_audit.json`：输入类型、零件映射、碰撞体覆盖率、可评分和不可评分原因。
- `pinv.jsonl`：有合格原始序列才输出该指标；包含动作数、首次失败、碰撞索引、明确的聚合口径。
- `glb_collision_proxy.jsonl`：仅 GLB 路线，单独输出最终场景诊断，不能伪装为 pinv。
- `vqa_qwen2vl_2b.jsonl`：每视角分数、主分数、最佳视角、失败原因。
- `config.json`、环境锁文件、输入/模型/代码哈希、运行时间和显存记录。
- 汇总 CSV、分类/等级表、配对差值表和 HTML 报告；与现有 SigLIP2/PE 按 sample_id 关联，保留缺失值，不合成未经验证的总分。

最先实施的具体任务是输入审计与 2B 小样本验证。若结构源数据仍缺失，报告中 P_inv 应标为“输入不足”，同时给经验证的 GLB 碰撞替代指标。
