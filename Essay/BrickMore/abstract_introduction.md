## Abstract

Generating brick structures from text requires both alignment with natural language and valid geometric connections between discrete pieces. We present BrickMore, a text-to-brick framework that combines large-language-model-assisted data construction, language-model fine-tuning, and post-generation geometric repair. Using GPT-6.1 Sol, we develop an automated voxel-generation pipeline that produces three-dimensional voxel coordinates in batches. The resulting shapes are converted into brick layouts through same-color tiling, connectivity analysis, and local bridging and retiling. The source dataset contains approximately 80,000 voxel models across 21 object categories on a 48³ grid. Each model has five English descriptions at different levels of detail, for approximately 400,000 descriptions in total. In the latest integrated version, nearly 80,000 models pass the specified geometric checks. We fine-tune Qwen3-1.7B using low-rank adaptation (LoRA) on English descriptions and brick-placement sequences, enabling it to predict brick dimensions and positions from text.

After generation, the pipeline forms a voxel union from the in-bounds portions of supported brick placements, uses mixed-integer linear programming (MILP) to seek an exact cover, and checks for a single stud-connected component. We evaluate the resulting structures against outputs from BrickGPT and BrickNet on 114 shared prompts. On the evaluated outputs, BrickMore achieves the highest mean scores across three text–image alignment metrics. It also obtains a mean invalid-placement ratio of 0.00%, matching BrickGPT under the same metric. These comparisons use a shared rendering protocol.

## Introduction

Text-to-three-dimensional generation enables users to describe and create objects using natural language. Generating brick structures adds the requirement that a target shape be represented as discrete pieces and their spatial placements. In addition to matching the text, the resulting structure must account for overlaps and connections between bricks: a layout may resemble the described object while containing intersecting bricks or disconnected parts, and thus fail to meet the specified geometric requirements.

Prior work has explored text-driven brick generation through different representations and generation constraints. [BrickGPT](https://arxiv.org/abs/2505.05469) trains an autoregressive language model on paired text and brick structures and applies validity checks and physics-aware rollback during inference (Pun et al. 2025). [BrickNet](https://arxiv.org/abs/2604.22984) uses a graph-based representation to generate assembly sequences involving a broader range of parts and connection types (Kulits and Schmid 2026). These works demonstrate the importance of structural representations and generation constraints for brick modeling.

For voxel-based shapes, spatial adjacency between voxels does not necessarily imply a valid connection between bricks. A voxel shape can form a connected volume even when the bricks covering it only touch side by side without stud connections. This distinction affects both data construction and generation: converting voxel shapes into training targets requires attention to coverage and brick connectivity, while predicted layouts may also contain overlaps or disconnected components that require further processing.

To study this problem, we present BrickMore. Using GPT-6.1 Sol, we develop an automated voxel-generation pipeline that produces three-dimensional voxel coordinates in batches, and we convert the resulting models into brick layouts. The source dataset contains 80,000 models across 21 object categories, represented on a 48³ grid, with five levels of English description for each model. We tile occupied voxels with same-color rectangular bricks and combine connection analysis with local bridging and retiling to address ungrounded components. Some derived targets involve limited changes to the source voxels; these changes and the original data are recorded separately. In the latest integrated version, 79,301 models pass the specified geometric checks.

We fine-tune Qwen3-1.7B with LoRA on English descriptions and brick-placement sequences. Given a text prompt, the model predicts brick dimensions and positions; the current output does not include color. To address potential overlaps and connectivity defects, we form a target union from the in-bounds voxels of supported brick placements, use MILP to seek an exact cover, and check for a single stud-connected component. For some cases in which no feasible layout is found within the solver's time budget, the system regenerates a sequence using a different language-model sampling seed. The connectivity check is geometric; physical stability and the feasibility of an assembly order require separate evaluation.

To evaluate the resulting structures, we compare the provided outputs of BrickMore, BrickGPT, and BrickNet on 114 shared prompts across 21 object categories and five description levels. We measure text–image alignment using VQAScore, PE, and SigLIP2, and evaluate the proportion of invalid brick placements using Pᵢₙᵥ. Under a common rendering protocol, BrickMore achieves the highest mean scores on all three text–image metrics. BrickMore and BrickGPT both obtain a mean Pᵢₙᵥ of 0.00% when evaluated in file order. These results describe the provided outputs under the specified evaluation protocol and do not independently establish physical stability or assembly feasibility.

Our contributions are as follows:

1. We develop an automated 48³ voxel data-generation pipeline with the assistance of a large language model, producing 80,000 source models across 21 categories, each with five levels of English description. In the latest integrated version, 79,301 models pass the specified geometric checks.
2. We develop a voxel-to-brick conversion pipeline that combines same-color tiling, connection analysis, and local bridging and retiling, while recording limited changes to source voxels in derived targets.
3. We fine-tune Qwen3-1.7B for text-to-brick generation and combine it with a post-generation pipeline based on voxel unions, exact-cover MILP, and connectivity checks。
