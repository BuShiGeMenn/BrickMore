# BrickMore-48 · 630 模型评测集(提示词 + 模型 + 人工判决)

> **[EN]** 630 LEGO brick models generated by `BrickGPT-Qwen3-1.7B-BrickMore-48` (48³ grid, 20 brick types), with full prompts, validation reports, LDraw files, generation manifests, failure autopsy and 5-person human judgment results. All 525 new-batch models are guaranteed assemblable (single stud-connected component). Text formats are lossless — models can be rebuilt in any LDraw/voxel tool.

本目录包含用 **BrickGPT-Qwen3-1.7B-BrickMore-48**(权重版本 `92d1c595`,48³ 网格,20 种砖型)生成的 **630 个乐高模型**,连同全部提示词、逐条验证报告、LDraw 文件、生成账本、失败病因解剖与五人人工判决结果。

## 1. 数据集构成

| 批次 | 数量 | 提示词来源 | 说明 |
|---|---|---|---|
| 新批 | 525 | 全新编写(21 类 × 5 等级 × 5 变体),与训练集零重叠 | 等级 L1→L5 描述复杂度递增(L4/L5 含明确尺寸);变体 V1→V5 为同等级不同措辞 |
| 首批 | 105 | 21 类 × 5 等级 × 1 变体(标记 `-A` / "首批") | 与新批同提示词框架,作为对照基准 |

每个"类 × 等级"构成一组(共 105 组),每组 6 个候选(525 批的 V1-V5 + 首批 1 条)参与人工判决。

## 3. 文件格式

每个模型目录包含(视availability):

| 文件 | 格式 | 说明 |
|---|---|---|
| `prompt.txt` | 文本 | 英文提示词 + 中文翻译 |
| `raw.txt` | 文本 | 模型**原始输出**,每行 `WxH (x,y,z)`。⚠️ 尺寸约定:第一个数是 **Y 方向宽度**、第二个数是 X 方向高度(模型原生 YX 约定);换算标准网格:`h=第二个数(沿X)`, `w=第一个数(沿Y)` |
| `raw_report.json` | JSON | 生成统计与验证结果(字段见下) |
| `stitched.txt` | 文本 | 数学兜底重铺后的布局,**标准尺寸约定** `HxW (x,y,z)`(h 沿 X、w 沿 Y),保证单一 stud 连通;无此文件 = raw 本身已可拼 |
| `raw.ldr` / `stitched.ldr` | LDraw | 对应版本的 LDraw 文件(每砖一行 `1 <color> <x> <y> <z> <旋转矩阵> <零件>.DAT`;Y 轴垂直,层距 24 LDu、格距 20 LDu,即真实乐高 1.2:1 比例),可直接用 LDView/Blender+ImportLDraw 打开 |
| `fix_note.json` | JSON | 仅首批 10 条:重叠 union 修复记录 |

`raw_report.json` 主要字段:`brick_count` 砖数 / `occupied_voxels` 体素数 / `voxel_components` 体素六连通分量 / `geometry_valid` 几何合法性(格式+白名单+边界+无重叠) / `errors` 错误明细 / `completed` 是否正常收尾(EOS) / `seconds`、`generated_tokens` 生成耗时与 token 数。

`manifest_w*.json` 每行字段:`category / level / variant / prompt / attempt`(种子,如 `@42`)/ `seconds / tokens / raw_bricks / voxels / union_dropped_bricks / solver_tier`(none_needed=raw 原生可拼,12s/60s/180s/600s=MILP 档位)/ `stitched / assembly_bricks / studOK / shape_preserved / raw_single_component / regen_seed / regen_history`。

## 4. 生成协议

1. **采样生成**:temperature 0.7,种子阶梯 42 → 104 → 2026(前一个种子产出不合格且不可修复时启用下一个);输出上限 8192 token;
2. **几何验证**(参考实现:作者本地包 `local_brickgpt/run.py::validate`):逐行格式、20 砖型白名单、48³ 边界、体素重叠、六连通分量;
3. **重叠 union 修复**:重叠砖的重复涂色格按一体素计,合并为目标体素集;
4. **MILP 保形重铺**(`local_brickgpt/single_stud_cover.py`,scipy HiGHS):精确覆盖 + 单一真实 stud 连通流约束,体素零增删;预算升级链 12s → 60s → 180s(→600s 极限档);
5. **stud 审计复核**:`single_stud_cover.audit` 独立复验(上下层凸点重叠建图,单分量 + 精确覆盖);
6. **不可解重生成**:升级链耗尽仍无解 → 换新种子重生成(28 条全部救回)。

## 6. 失败病因(raw_failure_autopsy.json)

对 479 条 raw 失败的量化解剖:

- **重叠只是小病**:50/479 (10%) 有重叠,其中 82% 仅 1-5 个重复体素(中位 2),union 即可修复;
- **主病 = "贴身不咬合"**(429/479, 90%):体素层完全连通(0 条体素散架),但按乐高规则(上下层凸点咬合)中位裂成 **5 个分量**;2240 块孤儿碎片中 **82% 紧贴主体**(距离 ≤1 格)——不是飞走的散件,而是**并排贴合却从不跨层交错**的柱/块(41% 自行落地成独立柱,59% 悬空侧贴);
- 结论:模型以"体素画师"方式堆砖(并排=连接),未掌握"每块砖与下层重叠 ≥1 格投影"的乐高咬合规则。该规则可一句话表述,为后续思考链蒸馏与解码期逐砖约束提供了明确靶点。

## 7. 人工判决(results/)

- **方法**:5 名评审各领一个分包(4/4/4/4/5 类),本地三维工具逐组比较 6 候选(360° 真零件渲染),每组选最佳或判"全部不合格";
- **结果**:105/105 组完成;**79 组 (75%) 有最佳,26 组 (25%) 全部不合格**;
- 最佳来源分布:首批 18 / V5 14 / V1 13 / V2 12 / V4 11 / V3 11 —— 首批(数据集风格短提示)胜出率最高,短提示生成更稳;
- 全不合格按类别:piano 5/5(全灭)、train 4/5、mug/pot 3/5;按等级:L1 3 → L5 8(越复杂越难合格);
- 零失败类别:camera / car / chair / guitar / bottle / jar / bookshelf / bed。
